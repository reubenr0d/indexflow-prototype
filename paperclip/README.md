# `paperclip/` — Paperclip-native mirror of the canonical IndexFlow company

This directory is a **generated mirror** of the canonical IndexFlow agent
sources, shaped to match what
[`paperclip-agent-companies-plugin`](https://github.com/alvarosanchez/paperclip-agent-companies-plugin)
v0.9.x expects.

## Why it exists

The plugin's content classifier (`classifyCompanyContentPath` in the worker
bundle) only recognises content at these exact paths, relative to the
source root:

| Content type | Required path |
|---|---|
| Company manifest | `COMPANY.md` |
| Paperclip extension sidecar | `.paperclip.yaml` (portable `agents[].adapter` + `inputs.env` metadata) |
| Agents | `agents/<slug>/AGENTS.md` (note: **plural**, **capital S**, inside a per-slug folder) |
| Skills | `skills/<slug>/SKILL.md` (at source root, NOT under `agents/`) |
| Projects | `projects/<slug>/PROJECT.md` |
| Tasks | `tasks/<slug>/TASK.md` OR `projects/<slug>/TASK.md` |
| Issues | `issues/<slug>/ISSUE.md` OR `projects/<slug>/ISSUE.md` |

Our canonical layout is flat (`agents/<slug>.md` files) because
[`scripts/agent-runner.mjs`](../scripts/agent-runner.mjs) reads them that
way. Rather than restructure the runtime (which would touch the runner,
the GitHub Actions workflows, the build-issue-context script, and ~15
documentation files), we mirror the canonical sources here.

## Source of truth

The canonical files live at the repo root:

- [`COMPANY.md`](../COMPANY.md)
- [`agents/self-improver-issues.md`](../agents/self-improver-issues.md)
- [`agents/issue-implementer.md`](../agents/issue-implementer.md)

The two prompt-only risk officers
(`agents/risk-officer-self-improvement.md`,
`agents/risk-officer-self-improvement-issues.md`) are **not** mirrored —
they're invoked inline by sibling scripts and have no heartbeat surface.
They stay documented in `COMPANY.md` `employees:` for org-chart visibility.

## DO NOT EDIT THESE FILES

Everything under `paperclip/companies/indexflow/` is **derived**. Edits made
here will be overwritten the next time `npm run sync:paperclip` runs.

To change the mirrored content, edit the canonical sources (at the repo
root and under `agents/`), then regenerate:

```bash
npm run sync:paperclip
```

## Adding the source to Paperclip

In the Paperclip UI:

1. `Settings → Repository Catalog → Add source`
2. Use the **absolute path to the mirror directory** (NOT the repo root):

   ```
   /Users/reuben/Desktop/minestarters/code/snx-prototype/paperclip/companies/indexflow
   ```

   Pointing at the repo root would trigger the plugin's recursive walker to
   discover BOTH the canonical root-level `COMPANY.md` (which the plugin
   would import with zero structured contents because the canonical agent
   files are at the wrong paths) AND the mirror's `COMPANY.md` — two
   "IndexFlow" companies with conflicting state.

3. `Discover → Import as new company` → IndexFlow appears with 2 importable
   agents.

See [`docs/PAPERCLIP_RUNBOOK.md`](../docs/PAPERCLIP_RUNBOOK.md) for the
full step-by-step.

## Promoting a brainstorm agent into the mirror

When a `brainstorm:` employee in `COMPANY.md` flips to `state: active`:

1. Author the prompt file at `agents/<id>.md`.
2. Add it to the `ACTIVE_RUNNABLE_EMPLOYEES` array in
   [`scripts/sync-paperclip-mirror.mjs`](../scripts/sync-paperclip-mirror.mjs)
   (so the agent file gets mirrored AND its `agents[<slug>]` block gets
   written into the generated `.paperclip.yaml`).
3. Add a matching `{ slug, requiredEnv, optionalEnv }` entry to the
   `ACTIVE_EMPLOYEES` array in
   [`scripts/paperclip-configure-adapters.mjs`](../scripts/paperclip-configure-adapters.mjs)
   so the post-import configure step knows to PATCH its adapter.
4. Run `npm run sync:paperclip`.
5. Commit the canonical file, both script changes, and the regenerated
   mirror in the same PR.
6. In Paperclip, re-scan the source — the new agent appears.
7. Run `npm run paperclip:configure-adapters` (idempotent) to wire the
   process adapter so the first heartbeat doesn't fail with `"Process
   adapter missing command"`.

## The `.paperclip.yaml` sidecar

[`companies/indexflow/.paperclip.yaml`](companies/indexflow/.paperclip.yaml)
is the portable Paperclip extension that
[`@paperclipai/server`](https://github.com/paperclipai/paperclip)'s
`company-portability.js` reads to learn:

- Which adapter type + base config each agent should use
  (`agents[<slug>].adapter`)
- Which env keys each agent declares as required vs optional
  (`agents[<slug>].inputs.env`)

It's generated by `npm run sync:paperclip` from
`ACTIVE_RUNNABLE_EMPLOYEES`. Two important caveats:

1. **`cwd` is intentionally omitted** — it's machine-specific. The
   `npm run paperclip:configure-adapters` script fills it post-import
   (auto-detected from the script location; override with
   `PAPERCLIP_REPO_ROOT`).
2. **`env` only declares the requirement** — `inputs.env` carries the
   names but cannot reference actual `secret_ref` IDs (those only exist
   inside a Paperclip instance's secrets store). The configure script
   resolves each declared name to its `secretId` and PATCHes the binding
   onto the agent.

As of plugin v0.9.1 the sidecar's `agents[].adapter.config` isn't fully
respected by the importer — the plugin only seeds the managed-instructions
keys, leaving `command`/`args` blank. That's why the configure script is
still required even though the metadata is portable. If a later plugin
build wires the portable `command`/`args` through, the configure script
becomes responsible only for `cwd` + env bindings.
